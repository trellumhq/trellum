start here · free & open source

Install the framework. Keep your repository.

Create a Python 3.11+ virtual environment in a new or existing repository, install the package from PyPI, then run python -m trellum for the CLI's own guide. Reports stay plain Python, SQL, YAML, and Git. Write them manually or ask your coding agent to work in the same files.

python -m pip install trellum

The framework is enough. Build and validate with python -m trellum.run reports/<name> --no-serve --portable, then open the output on your laptop, publish it from CI, or serve it from any static host. The optional self-hosted portal adds managed schedules, authentication, and team sharing.

how a report is actually built

Your sources. Joined in Python. One report.

Use built-in connectors for supported databases and files. For other services, call their Python SDKs. Your report code chooses what to load, how to transform it, and which reusable datasets feed each component.

Postgres & SQL Snowflake BigQuery DuckDB CSV & Parquet Excel files custom Python + more databases

Bring your sources together. Load a file and warehouse table, call an API through its SDK, then join the resulting DataFrames in ordinary Python.

✓ configured caches can speed up repeated local builds

Your deployment stays yours. Run locally, in CI, or on infrastructure you control. You choose where generated report data is stored and served.
Transform in plain Python. Joins and reshaping are explicit DataFrame operations in your report code, so reviewers can see what changed.
Cache when it helps. Configure query caching for repeated builds. Changed SQL, expired entries, or a cache bypass can query the source again.

⚡ live is an option, per report: for reports that need fresh data at view time, configure a live-query backend and let viewers choose their parameters.
